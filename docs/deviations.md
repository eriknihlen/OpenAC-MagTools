# Deliberate deviations from the original Mag-Tools

A rolling table of every place this port knowingly behaves differently from
the original Decal plugin, why, and where to look. Anything not listed here
is intended to be behavior-identical. `docs/2026-09-16-port-design.md` §7
covers the separate "not applicable" list (Decal/Win32-only features with no
OpenAC equivalent) — this table is for features that DO exist here but work
slightly differently.

| Area | Original behavior | This port | Why | Where |
|---|---|---|---|---|
| Settings save | Rewrote the whole XML file on every single setting assignment. | Marks the document dirty and flushes at most once per 250 ms debounce; `Disable()` flushes synchronously. | Avoids a storage write per keystroke/toggle; semantics stay write-through (a reader always sees the new value immediately). | `src/OpenAC.MagTools/Settings/SettingsFile.cs` (`SaveDebounce`) |
| Settings account scoping | Concatenated the raw account name into an XML element name unescaped — invalid XML for any account name containing spaces or most punctuation. | `XmlConvert.EncodeName` on both the account and server name before building the scope element name. | Fixes a real original bug rather than reproducing it; the encoding is the identity transform for an ordinary alphanumeric account, so this only changes behavior for names that would otherwise have broken the document. | `src/OpenAC.MagTools/Settings/SettingsScope.cs` |
| Login banner population | Always printed a population number, defaulting to whatever Decal's proxy last cached (sometimes stale or zero). | Omits the population clause entirely when the host hasn't yet reported it (`ICharacterInfo.ServerPopulation` is `-1` until the login-time world-name message arrives), instead of printing a wrong or stale number. | The host's population figure is a one-time snapshot that may not exist yet at the exact moment the banner prints; printing nothing is preferable to printing 0 or a stale figure. | `src/OpenAC.MagTools/SessionContext.cs` (`OnLoginComplete`), `src/AcDream.Plugin.Abstractions/Automation.cs` (`ICharacterInfo.ServerPopulation`) |
| `/mt fellow create` | Drove the retail fellowship-creation dialog by clicks; the share-experience checkbox's actual state depended on whatever the user last left it at. | Always calls `Fellowship.Create(name, shareExperience: true)`. | The automation surface's `Create` takes `shareExperience` as a real parameter, but no `/mt fellow create` argument surface exists yet to pass a user choice through — `true` is a fixed default, not a rediscovered original default. Revisit if a demand for `shareExperience: false` shows up. | `src/OpenAC.MagTools/Commands/MtCommandRouter.cs` (`Fellowship`) |
| `usel <item> on <target>` (and the plain `use A on B` form) | Resolved without keyword matching: `A` is always looked up inventory-only, `B` is resolved in the command's own scope (inventory/landscape/anywhere) and is never allowed to resolve to the same object as `A`. | Ported as-is: `FindIdForName` for the source is always `searchInventory: true, searchOpenContainer: false, searchEnvironment: false`; the target search additionally passes `idToSkip` = the source's id. | Faithful port, called out here because it looks asymmetric (source is inventory-only, target is scope-wide) if you only read the target-side call. | `src/OpenAC.MagTools/Commands/MtCommandRouter.cs` (`Use`, `FindIdForName`, `idToSkip`) |
| Name-lookup search breadth (`FindIdForName`) | Two-pass lookup: an exact-name pass over inventory, then the open container, then the closest landscape object; only if that finds nothing AND partial matching was requested does the same three passes repeat with a substring match. | Ported as-is, with `idToSkip` threaded through every pass so a command that already resolved a source object never lets a target search re-select it. | Documented here because the exact/partial split and the pass order are easy to "simplify" by accident during a future refactor — don't. | `src/OpenAC.MagTools/Commands/MtCommandRouter.cs` (`FindIdForName`, `FindPass`) |
| Trade/buff-bot spam filter | Matched two composed-text regex shapes: another player's LOCAL SAY ending in `-t-"`/`-b-"` (quote included, from the wrapping `says, "..."`), or ANY non-chat line ending in `-t-`/`-b-` (no quote). | Split by structured Kind instead: `IsMine && IsChat` local speech ending in `-t-`/`-b-` (no quote — the bare `Message` never carries one), OR an `Emote`/`SoulEmote` kind specifically ending in `-t-`/`-b-`. | The composed-text "local say" half only ever matched another player's speech (never the local player's own, since that regex required the `<Tell:...>` markup `PlayerSaysLocal` uses); the "any non-chat line" half was really only ever hit by third-person emotes in practice. Reading the structured fields makes both halves precise instead of relying on regex accidents. | `src/OpenAC.MagTools/Chat/ChatFilter.cs` (`TradeBuffBotSpam`) |

| Item info ident detection (user path) | Gated `RequestId` on a real `WM_LBUTTONDOWN` message followed by a selection within 1 second. | Every `ISelectionService.Changed` IS treated as the click — the host contract has no raw click event. | The host exposes deliberate selection (a click or a select command) but not the raw mouse message the original distinguished a click from. | `src/OpenAC.MagTools/ItemInfo/IdentDetector.cs` (`UserIdentDetector`) |
| Inventory export sort: equipped ordering | Ordered equipped items within the main pack by `EquippedSlots`, a count of how many equip slots the item occupies. | Orders by `PluginInventoryItem.EquippedLocation`, the equip-slot bitmask itself, since the host has no occupied-slot count. | The host contract has no matching field; the bitmask gives a stable, deterministic order that usually but not provably matches the original. | `src/OpenAC.MagTools/Inventory/WorldObjectSorter.cs` |
| Item info line: clickable `<Tell:...>` prefix | The line's marker/rule prefix was wrapped in a `<Tell:IIDString:221112:objectId>...<\\Tell>` tag, making it a clickable name in the chat window. | Emits the plain `marker + ruleTag + " " + info` form — no wrapper. | The host's chat markup parser (`AcDream.Core.Chat.ChatTagMarkup`, gated by `ChatVM.ShouldTagSender`) only parses that tag for speech `ChatKind`s (LocalSpeech/RangedSpeech/Channel/Tell); a plugin-posted line is never one of those kinds, so the tag would render as literal text instead of a clickable link. | `src/OpenAC.MagTools/ItemInfo/ItemInfoPrinter.cs` (`PrintWithVerdict`) |
| Item info format: buffed-value math vs. active spells | `GetBuffedIntValueKey`/`GetBuffedDoubleValueKey` subtracted the `Change` of every ACTIVE spell effect on the item (buffs currently in effect), in addition to adding the item's own carried-spell `Bonus`. | The active-effect half is always a no-op for anything but the local player: `ICharacterInfo`/`PluginWorldObject.ActiveSpellIds` is empty for every object except the local player (`AppAutomationSurface.cs`, `BuildWorldObject`) — the host has no per-object active-enchantment list yet. | Reading another object's live active enchantments isn't wired up in the automation surface; until it is, buffed values for anything but your own equipped gear only reflect the carried-spell `Bonus` half. | `src/AcDream.App/Plugins/AppAutomationSurface.cs` (`BuildWorldObject`), `src/OpenAC.MagTools/ItemInfo/ItemModel.cs` (`GetBuffedInt`/`GetBuffedDouble`) |
| Loot rule verdict: ManaStone/ManaTank forward-compat | Not a deviation from the original — `Matched && Action != NoLoot` is the original's own `!result.IsNoLoot` check, restored verbatim. | The CURRENT OpenAC snapshot's shared `PluginLootAction` enum has no `ManaStone`/`ManaTank` members yet, so the classifier registry reports those two specific keep-rules as `Matched:true, Action:NoLoot` — a host artefact, not a real NoLoot verdict. `LootRuleProcessor.Classify` also checks the action's name against `"ManaStone"`/`"ManaTank"` via `Enum.TryParse` (never a direct `PluginLootAction.ManaStone`/`.ManaTank` reference, since those members don't exist in this snapshot). | OpenAC is adding the two members; this keeps the plugin compiling against both the current snapshot (the name check is a harmless no-op today) and the fixed one (the literal `Action != NoLoot` check already passes them once they're real distinct values). | `src/OpenAC.MagTools/ItemInfo/LootRuleProcessor.cs` (`Classify`, `IsManaRuleAction`) |
| Item info format: unresolvable carried-spell id | Indexed the spell table directly with no presence check — an id the table doesn't have would have thrown, taking the whole item-info line down with it. | Skips a spell id the catalog can't resolve and keeps building the rest of the line. | A missing spell id is not something this port should turn into a crashed appraisal line; every other segment already degrades gracefully (unknown skill/material/mastery names print a placeholder instead of throwing). | `src/OpenAC.MagTools/ItemInfo/ItemInfoFormatter.cs` (`AppendSpells`) |
| Combat tracker: `CombatTrackerGUIInfo` typeless-magic bug (Appendix B item 2) | `updateCombatTrackerGUIInfo` assigned `combatTrackerGUIInfo.TypelessMeleeMissile` twice (the second assignment should have been `TypelessMagic`), so the typeless-magic cell never filled in. | `CombatTrackerRows.BuildDamageRows` assigns each cell exactly once, correctly: the Typeless row's Magic column reads the typeless-magic bucket. | Fixing an obvious upstream bug, not reproducing it — nothing else depended on the broken cell staying blank. | `src/OpenAC.MagTools/Trackers/Combat/CombatTrackerRows.cs` |
| Combat tracker: `MeleeMissileGivenAttacks` regex order (Appendix B item 5) | The plain `^You [\w]+ ... $` pattern was table index 1 (right after the plain crit pattern), ahead of the Sneak-Attack/Recklessness variants. | The specific patterns (Sneak, Sneak+Reckless, Reckless, then plain-crit) are ordered before the general `^You ...` pattern. | Matches the design doc's explicit fix instruction. Verified this does NOT change which lines match any known retail shape — under .NET's default (non-Multiline) anchoring, `^You` cannot match a line that starts with the literal "Sneak Attack!"/"Recklessness!" text, so the two orderings are behaviorally identical; the reorder removes a maintenance/readability hazard rather than fixing an observed misparse. | `src/OpenAC.MagTools/Chat/CombatMessages.cs` (`MeleeMissileGivenAttacks`) |
| Combat tracker: parser subscription count | Two chat-event subscriptions (one per `StandardTracker`/`AetheriaTracker`/`CloakTracker` instance, since the original built one full tracker set per `CombatTracker`, and there are two `CombatTracker`s — current + persistent). | One subscription (`CombatTrackerHost.OnReceived`) parses each line once via the now-static, stateless `StandardTracker.Parse`/`AetheriaTracker.Parse`/`CloakTracker.Parse` and forwards the same result to both the current-session and persistent `CombatTracker` instances. | Avoids parsing every combat line twice for no behavioral difference; the original's per-instance subscription was an implementation artifact of C# events, not an intentional design point. | `src/OpenAC.MagTools/Trackers/Combat/CombatTrackerHost.cs`, `StandardTracker.cs`, `Aetheria/AetheriaTracker.cs`, `Cloaks/CloakTracker.cs` |
| Combat tracker: "is this a combat line" gate | Every tracker independently ran `Util.IsChat(e.Text)` against retail's COMPOSED display text to skip ordinary chat before pattern-matching — retail's own gate saw every chat-box line except player chat, combat or not. | Gates on the host's structured `PluginChatMessage.Kind is Combat or System` (via `ChatClassifier.Classify`), excluding `IsChat` lines, before any regex runs. On this host only the lines `CombatChatTranslator` composes (damage dealt/taken/missed/evaded) and the retail Victim/KillerNotification kill messages carry `Kind == Combat`; server-composed combat-ADJACENT text (spell damage, resists, magic-cast fizzles, aetheria surges, cloak surges, Dirty-Fighting notices) rides the host's generic `WeenieError`/text path and arrives as `Kind == System` instead. An earlier revision of this port fed only `Combat`, which matches host-composed evade/damage/kill lines but silently starved `AetheriaTracker`/`CloakTracker` (they never saw a `Combat`-kind line to parse) — this row was rewritten to record that correction. | The host already tells a plugin which lines are combat-shaped; re-deriving that from composed text would be strictly worse, and restricting to `Combat` alone drops two of the three sub-trackers this host feeds. | `src/OpenAC.MagTools/Trackers/Combat/CombatTrackerHost.cs` (`OnClassified`) |
| Combat tracker: resisted-attack chat line gap | N/A — retail always emits a chat line for a resisted/evaded attack. | `CombatState.cs`/`CombatNotificationText.cs` in the acdream host worktree were checked; the host's evade/resist text shapes are covered by `CombatMessages.FailedAttacks` as-is. A separate gap WAS found and fixed: a hostile monster's AI can use Sneak Attack/Reckless against the local player too, and neither `MeleeMissileReceivedAttacks` nor `MagicReceivedAttacks` anchored past those prefixes, so a received line carrying one had its prefix swallowed into the attacker's name by the greedy leading `targetname` group. `CombatMessages.StripReceivedPrefixes` strips `"Sneak Attack! "`/`"Reckless! "`/`"Recklessness! "` before matching the received tables. That prefix is not always at the very start of the line, either: `CombatNotificationText.DefenderLineForBodyPartText` writes `"Critical hit! "` (or `"Overpower! "`) BEFORE the Dirty Fighting text, e.g. `"Critical hit! Sneak Attack! <name> mangles ..."`, so `StripReceivedPrefixes` also pulls off a leading `"Critical hit! Overpower! "`/`"Critical hit! "`/`"Overpower! "` anchor first, strips the Dirty Fighting text behind it, then re-prepends the anchor so the received tables' own crit/overpower literal still matches. Also: `CombatNotificationText.DefenderLine` (the host's incoming-reckless-attack line) emits `"Reckless! "`, not `"Recklessness! "` — only the outgoing `AttackerLine` uses the longer word — so `StandardTracker.Parse`'s `isRecklessness` flag now accepts both spellings. | Recorded per the P4 task brief's instruction to note this as a gap rather than inventing a translator in OpenAC (which this port must not modify); the prefix-stripping and spelling-alias fixes are host-text-shape corrections within this port's own regex tables, not a change to OpenAC. | `docs/2026-09-16-port-design.md` §2.1, `src/OpenAC.MagTools/Chat/CombatMessages.cs` (`StripReceivedPrefixes`), `src/OpenAC.MagTools/Trackers/Combat/StandardTracker.cs` |
| Combat/damage list layout | A real `HudList` with per-column pixel widths (5 columns for the monster list, 5 for the damage list) — genuine multi-column alignment, numeric columns right-aligned. | Also a real multi-column list: the host's `<list>` DOES support `<column type="text" width="N">` children (see docs/plugin-ui-markup.md and this port's own Mana/Corpse/Player/Inventory/Chat tabs) — the earlier single-string-row collapse was an unjustified simplification, not a UI-surface limitation. Rebuilt as monster list columns 111/37/55/* (Name/KB's/Dmg Rcvd/Dmg Givn) and damage list columns 40/52/52/45/* (Label/Mel-Msl/Magic/StatLabel/StatValue), bound to per-column `IReadOnlyList<string>` properties (`CombatTrackerRows.MonsterRow`/`DamageRow`). Every VALUE and PERCENTAGE computation is still byte-for-byte the same math as the original. **Right-alignment itself is NOT reproduced and cells are left unpadded** — the markup's `<column>` has no alignment attribute, and the host's `UiMarkupList` draws each cell left-aligned and CLIPS it to the column's pixel width with no ellipsis (`UiMarkupList.cs`'s `DrawTextCell`/`PushClip`, confirmed against the current OpenAC source). A left-padded numeric string (an earlier revision of this row tried `PadRightAligned`, padding e.g. the 55px `Dmg Rcvd` column to 10 characters and the two 52px damage columns to 9) would have its LEAST-SIGNIFICANT digits pushed toward the clip edge and silently cut off whenever the padded width exceeds what the column's pixel width actually fits — worse than plain left-alignment, which the original port design's column widths already guarantee fit for every value this tracker produces. | The markup limitation this row originally cited (no multi-column primitive) does not exist; the multi-column list primitive was always there. Right-alignment genuinely cannot be reproduced without an alignment attribute the host doesn't have, and faking it via padding actively loses data rather than merely looking different — a real, permanent visual deviation, not an approximation. | `src/OpenAC.MagTools/Trackers/Combat/CombatTrackerRows.cs`, `src/OpenAC.MagTools/Views/magtools.xml` |
| Combat tracker: DPS-window pruning | The original's `ValueSnapShotGroup.AddSnapShot(DateTime, int, int minutesToRetain = 0)` HIDES (not overrides) the base `SnapShotGroup<int>.AddSnapShot(DateTime, int)` — the original's `CombatTracker` called the 2-argument shape, which resolves to the derived 3-argument overload with its default `minutesToRetain = 0`, and `Prune` no-ops for `minutesToRetain <= 0`. So the original's DPS snapshots were NEVER pruned, for the life of the tracker. | `CombatTracker.OnCombatEvent` explicitly passes `DpsRetentionMinutes` (60) as the third argument, so this port's snapshots ARE pruned to a 60-minute rolling window. | Unbounded per-second DPS snapshot growth for an entire play session is a real memory leak with no offsetting behavior benefit (the DPS readouts only ever look at the last 1/5/60 minutes) — this is a deliberate correction, not a faithful reproduction of the overload-shadowing bug. | `src/OpenAC.MagTools/Trackers/Combat/CombatTracker.cs` (`OnCombatEvent`), `Trackers/ValueSnapShotGroup.cs` |
| Chat classification fan-out | `ChatLogger` and `CombatTrackerHost` each subscribed to the raw chat feed independently and each called `ChatClassifier.Classify` on the same message — every delivered line was classified twice for no behavioral difference (classification is a pure function of the message and the automation surface). | `ChatClassificationDispatcher` subscribes to the raw feed exactly once, classifies once, and fans the same message + `ChatLine` out to both consumers (and any future filter-independent one, e.g. a mana-recharge listener). Both constructors take an optional dispatcher; without one they fall back to their original self-contained classify-inline behavior (used by existing unit tests that construct them directly). | Removes a redundant classification pass per delivered chat line with no behavioral change — every existing classification/gating rule is unchanged, only WHERE `Classify` runs moved. | `src/OpenAC.MagTools/Chat/ChatClassificationDispatcher.cs`, `Loggers/Chat/ChatLogger.cs`, `Trackers/Combat/CombatTrackerHost.cs`, `MagToolsPlugin.cs` |
| Combat monster-list row marker | Column 0 held a `"*"` glyph on the selected row, redundant with the list widget's own selection highlight. | Dropped — the host's `<list selectionband="true">` already highlights the selected row, so there is no separate marker column. | The host's list widget already shows selection state; a text marker column would be pure duplication. | `src/OpenAC.MagTools/Trackers/Combat/CombatTrackerRows.cs` |
| DPS window clock | Hardcoded `DateTime.UtcNow` throughout `SnapShotGroup`/`ValueSnapShotGroup`. | Takes a `TimeProvider` (default `TimeProvider.System`). | Lets a test inject a fake clock and assert exact DPS-window numbers instead of racing the wall clock; `TimeProvider.System` reproduces the original's behavior exactly when no fake is supplied. | `src/OpenAC.MagTools/Trackers/SnapShotGroup.cs`, `ValueSnapShotGroup.cs` |
| Combat tracker: `Av/Mx`/`Crits` cells when their denominator is non-positive | The GUI simply never called the corresponding `Set...` method when its guard failed, leaving that cell showing whatever it last displayed (stale, from `Clear()` or the previous selection). | Renders blank (`""`) whenever the corresponding denominator is `<= 0`. | This port rebuilds the whole row list fresh on every access rather than mutating a persistent widget — there is no "last displayed value" to fall back to, so blank is the only coherent choice. | `src/OpenAC.MagTools/Trackers/Combat/CombatTrackerRows.cs` (`BuildDamageRows`) |
| Combat tracker DPS math: zero-elapsed-window division | `GetValueDifference`/`GetDamageGivenOverTime` divide by the elapsed time since the closest historical sample with no zero guard; a query made in the same instant as the only sample divides by zero, producing `+Infinity`. | Ported as-is (no added guard) — flagged here because it looks like a bug worth "fixing" at a glance. | Self-corrects within a second or two of real play once more samples land; guarding it would be an undocumented behavior change from the original for an edge case that never persists. | `src/OpenAC.MagTools/Trackers/Combat/CombatTracker.cs` (`GetOverTime`) |
| Combat tracker storage keys | `<PluginPersonalFolder>\<Server>\<Character>.CombatTracker.xml` / `...yyyy-MM-dd HH-mm.xml` via `System.IO`. | `IPluginStorage` text keys `<Server>/<Character>.CombatTracker.xml` and `<Server>/<Character>.CombatTracker.<yyyy-MM-dd HH-mm>.xml` — same naming, forward-slash key separator (the storage abstraction's convention, matching `ChatLogFileStore`'s existing `StorageKey`). | The host's storage contract is a flat text-key store, not a real filesystem; naming otherwise matches exactly. | `src/OpenAC.MagTools/Trackers/Combat/CombatTrackerHost.cs` |
